# ADR-012 v0.6 Amendment：收缩 Delivery 语义控制，恢复 Authoring 自主性

* **状态**：提议
* **阶段**：Delivery / Report Generation
* **版本**：v0.6
* **基于**：ADR-012「通过 Report Brief 与双重审校闭环生成最终报告」
* **性质**：ADR-012 的修订，不新增 ADR
* **影响范围**：Report Construction、Report Brief、Authoring、Fresh Reader、Research Integrity、Delivery Runtime、Report Guides
* **不影响**：Research State authority、Completion authority、Research lifecycle、Primary Evidence Gate、citation rendering、Wiki

---

## 1. 为什么是 Amendment，而不是新的 ADR

v0.6 不改变 ADR-012 的核心 authority topology：

```text
Research State
→ Report Construction
→ Report Brief
→ Authoring
→ Reader Gate
→ Research Integrity
→ deterministic Presentation
→ Publish
```

以下决策继续成立：

* Research State 是唯一研究事实权威；
* Completion 决定 Research 是否足以进入 Delivery；
* Report Brief 是唯一报告语义中间层；
* Delivery 不建立独立 Report lifecycle / FSM；
* Reader 与 Research Integrity 保持独立；
* semantic change 使依赖该版本的 downstream certification 失效；
* 问题返回最早有资格修复它的 authority；
* Python 负责机械不变量，Agent 负责语义判断。

v0.6 修改的是 ADR-012 对这些 authority **内部如何工作**的具体设计，而不是增加新的 authority、lifecycle、gate 或 semantic layer。

因此本修订属于 ADR-012 内部校准。

---

## 2. 问题

v0.5 试图通过更完整的 Report Brief、更详细的 Writing / Review 标准和 Fresh Reader 闭环，提高最终报告质量。

真实 E2E 表明，这些机制虽然提高了局部正确性，却同时产生了新的系统性失败。

### 2.1 Report Brief 从 Editorial Intent 漂移为 Manuscript Specification

v0.5 Brief 逐步包含：

```text
report title
conceptual model
reader takeaway
narrative logic
section tree
section purpose
semantic moves
outline depth
research refs
material
reader-visible obligation
evidence boundary
terminology
intentional omissions
```

这些字段使 Constructor 不再只是决定：

> 这篇报告应该让读者理解什么。

而开始提前决定：

> 文章用什么章节、按什么步骤、消费哪些材料、哪些细节必须显式出现。

结果是 Authoring 局部自由仍在，但全局实现空间已经被预编译。

### 2.2 Material obligation 把 Research richness 转换成正文压力

`BriefMaterial` 与 `reader_visible_obligation` 让某项研究材料从：

> 可供 Authoring 使用的支持

变成：

> 必须进入读者认知的交付义务。

这会系统性偏向方法覆盖、数字覆盖、公式恢复、条件逐项说明、对称分类与局部论证闭合。

单个材料都可能“有用”，但整体仍然形成过密、method-heavy、inventory-like 的成品。

### 2.3 Quality / Writing / Review 对同一 concern 重复编码

v0.5 中，认知连续性、材料经济性、论证完整性、专业中文、全文闭合等 concern 被：

```text
REPORT_QUALITY_STANDARD
→ 定义为质量目标

REPORT_WRITING_GUIDE
→ 翻译成生成行为

REPORT_REVIEW_GUIDE
→ 再翻译成检查行为
```

同一个 concern 被多次显式化后，模型更容易生成“符合规范的文章”，而不是自然成立的文章。

### 2.4 Fresh Reader 从验收 Gate 漂移为优化器

Reader 输出被扩展为：

```text
domain model
comparison coordinates
reverse outline
material economy
professional finish
cognitive friction
blocking issues
...
```

reference pipeline 又通过：

```text
Reviewer
→ Reviser
→ NEW Reviewer
→ Reviser
→ ...
```

持续运行到 PASS。

这让 Fresh Reader 从低频的独立验收工具，变成高频的 critic-driven optimization loop。

修复往往是增量式的：增加解释、限定、公式、过渡和显式关系，因此局部问题减少时，全文密度与模板感反而可能上升。

### 2.5 现有设计错误地把“质量可靠”与“控制更多”绑定

v0.5 的失败不说明 Reader、Brief 或 Integrity 不应存在。

它说明：

> **每个模块都不应通过显式化更多质量概念来承担额外控制。**

Delivery 的可靠性应该主要来自 authority boundary 正确、context surface 合理、producer 有足够能力、acceptance gate 独立，以及 deterministic runtime 不变量可靠，而不是通过逐步增加字段、rubric 和 Reviewer 检查项获得。

## 3. 新的 Delivery 原则

v0.6 将 Delivery 定义为：

> **从已接受研究语义到读者成品的选择性编译。**

Research 需要尽量保留重要知识、证据、冲突和边界。

Delivery 则必须主动舍弃不会实质改变目标读者理解的研究复杂度。

因此：

```text
Deep Research
→ Lean Editorial Design
→ Strong Authoring
→ Light Reader
→ Strict Integrity
```

核心原则：

> **Production Harness 的复杂性来自 authority boundary 与 deterministic safety，而不是来自“优秀写作表现”的完整枚举。**

---

## 4. v0.6 总体流程

默认路径：

```text
Research State
→ Completion PASS
→ Report Construction
→ Lean Report Brief
→ Authoring
→ Manuscript
→ deterministic Presentation
→ Fresh Reader
→ Research Integrity
→ deterministic final render
→ Publish
```

修复路径是异常路径，不是默认优化过程：

```text
Reader
├─ PASS
├─ MANUSCRIPT → Authoring → new Manuscript → Fresh Reader
└─ BRIEF      → Constructor → new Brief → Authoring → Fresh Reader

Integrity
├─ PASS
├─ MANUSCRIPT → Authoring → Fresh Reader → Integrity
├─ BRIEF      → Constructor → Authoring → Fresh Reader → Integrity
└─ RESEARCH   → reopen Research
```

v0.6 不引入 Style Reviewer、Polish Stage、Editorial Score、Quality Score、Material Score、Reader Iteration State、新的 Report lifecycle 或新的 semantic IR。

---

## 5. Report Brief 仍存在，但只表达 Editorial Intent

### 5.1 Brief 的存在理由

Research State 回答：

> 当前 Research Contract 下，我们有资格认为哪些研究判断成立？

Report Brief 回答：

> 对于这一次交付，我们决定让当前读者形成什么核心理解？

这个差异仍然需要独立中间层，因此 Report Brief 保留。

### 5.2 Lean Report Brief

v0.6 Brief 只保留：

```text
audience
promise
frame
arc
focus
```

`audience` 是当前报告的目标读者假设。v0.6 暂时继续放在 Brief 中以控制改动范围；语义上它继承用户 / Contract 的交付约束，不是 Constructor 可任意重新选择的编辑变量。

`promise` 回答：

> **这篇报告最终承诺交付什么理解？**

`frame` 是贯穿全文的主要解释框架。它应该帮助解释为什么问题出现、主要 intervention 改变了什么、不同路线为什么产生不同 trade-off。它不要求 taxonomy、矩阵或固定分类。

`arc` 描述读者理解大体如何从起点发展到最终判断。它表达 semantic dependency，而不是 section tree，不要求一项对应一个 H2，也不规定段落顺序。

`focus` 描述有限读者注意力如何分配：什么是主体、什么只是背景、哪些内容值得深入、哪些内容不需要穷举。它控制 editorial attention，而不是 token budget 或 material quota。

## 6. 以下内容退出 Report Brief

v0.6 删除：

```text
report_title
report_goal
conceptual_model
reader_takeaway
narrative_logic

ReportBriefSection
section title
section purpose
section takeaway
semantic_moves
outline_depth
requirement_refs
research_refs
material[]
reader_visible_obligation
evidence_boundary

terminology
intentional_omissions
```

这些信息有三种去向：

1. 已被 `promise / frame / arc / focus` 在更高抽象层表达；
2. 属于 Authoring realization；
3. 属于 upstream Research / Contract authority，不应复制到 Brief。

原则：

> **任何不会改变“这是不是同一篇报告”的信息，都优先不进入 Brief。**

---

## 7. Constructor 的职责收缩为 Editorial Design

Constructor 的唯一主要责任：

> **在 accepted Research semantics 与有限读者注意力之间做编辑选择。**

Constructor 决定 `Promise / Frame / Arc / Focus`。

Constructor 不再决定最终标题、reader-visible heading、section count、section depth、paragraph plan、具体论文/数字/公式是否必须出现，或 material consumption plan。

Constructor 可以使用 narrow Research context，并按需 inspect / read-source，以确认当前 accepted semantics 能支持怎样的编辑设计。

但 Constructor 不得因为 source reading 创造新的 Research judgment。

如果无法在当前 accepted Research basis 上形成忠实满足 Contract 的 Brief，则返回 Research，而不是在 Delivery 中制造新的研究结论。

---

## 8. Authoring 恢复局部与结构实现权

Authoring 负责：

> **把 Lean Report Brief 实现为自然、成熟、专业的完整文章。**

Authoring 拥有：

```text
final title
visible outline
section merge / split
paragraph organization
local ordering
prose / list / table choice
representative method selection
representative paper selection
whether exact metric is reader-visible
whether formula is reader-visible
local explanation depth
language rhythm
citation placement
```

Authoring 必须保持 `Promise / Frame / Arc / Focus`，但不把 Brief 当作 checklist。

原则：

> **Brief contains intent. Research support exposes possibilities.**

---

## 9. Authoring 获得 semantic-first、read-only Research Support

删除 `BriefMaterial` 后，Authoring 不再只依赖 Brief 与 paper metadata。

v0.6 为 Authoring 提供一个薄的、可重建的只读 projection。

默认暴露：

```text
Contract / delivery description
Approach semantics
Accepted Findings
Accepted Open Problems
```

默认不暴露：

```text
paper inventory
source inventory
URLs
raw locators
InvestigationGap work queue
```

当精确 realization 需要代表论文、具体数字、实验条件、公式或 primary citation 时，Authoring 可以使用现有 targeted read-only Delivery access：

```text
inspect accepted semantic object
→ inspect supporting retained paper
→ targeted read-source
```

Authoring 不获得 search、retain、retire、Research State mutation 或 Finding / Approach / OpenProblem creation 能力。

如果 Brief 无法忠实、自然地实现，Authoring 使用 `BriefInsufficient` 返回 Constructor。

---

## 10. Writing Guide 从规则手册收缩为 Authoring Charter

v0.6 不再把以下 heuristic 作为 Production contract：

```text
一个段落只完成一个任务
判断 → 证据 → 限制 → 含义
固定开头模型
固定执行摘要建议
taxonomy 构造规则
段首规则
长句拆分规则
AI-like 词语清单
抽象名词密度测试
material consumption checklist
固定 transition 模式
```

这些内容不迁移到 Reader 或 Quality Standard。

Authoring Charter 只保留：

* 忠实实现 Brief；
* 自然、成熟、专业地完成目标语言文章；
* 研究材料服务于理解，而不是展示研究库存；
* 不创造新的研究判断；
* Brief 无法自然实现时返回上游。

原则：

> **写作质量主要依赖 Authoring 能力，而不是通过生产 Prompt 枚举所有优秀写作表现。**

---

## 11. Fresh Reader 收缩为 Acceptance Gate

Fresh Reader 不负责让报告变好。

它只负责暴露：

> 当前 Manuscript 是否已经足够作为成品成立。

### Phase 1 — Blind Reading

输入：

```text
deliverable description
audience
Reader Surface
```

不输入 Report Brief、Writing Guide、Research State、prior review、repair history 或 Integrity result。

输出只需：

```text
received_understanding
blocking_issues
```

Blocking issue 只描述真实 reader failure：

```text
problem
reader_effect
optional location
```

不输出 domain model ontology、comparison coordinates、reverse outline、material economy analysis、professional finish analysis、cognitive friction list、resolution condition、repair recipe 或 quality score。

### Phase 2 — Brief Attribution

Phase 2 在 Blind Result 冻结后执行。

输入：

```text
Frozen Blind Result
Report Brief
delivery requirements
```

Phase 2 不重新读取 Manuscript / Reader Surface。

它只回答：

1. Blind Reader 实际获得的理解是否与 Brief / delivery requirement 兼容？
2. 如果存在 blocking mismatch，最早属于 `MANUSCRIPT` 还是 `BRIEF`？

Phase 2 不发现新的 prose issue，也不规定修复方法。

Blind Reading 与 Brief Attribution 应使用隔离的 fresh invocation；两阶段唯一的信息桥梁是冻结的 Blind Result。这仍然是同一个 Reader Gate，不新增新的 semantic authority。

---

## 12. Reader PASS 的含义

Reader PASS 不表示报告完美。

只表示：

> **当前版本没有真实 reader blocker，并且实际读到的报告与当前 Editorial Brief 和交付要求兼容。**

Reader 不负责技术 proof、数字核验、citation evidence audit、benchmark 公平性或 exact equation verification；这些属于 Research Integrity。

Reader 不输出 nonblocking improvement list。

原则：

> **没有 blocker，就是 PASS；PASS 以后不继续利用 Reader 优化文章。**

---

## 13. Reader repair 不再是 convergence loop

v0.6 撤销 ADR-012 中：

```text
Reviewer → Reviser → NEW Reviewer ↺
```

作为默认“运行到 PASS”的优化语义。

新的规则：

```text
Reader FAIL
→ earliest qualified owner performs a coherent repair
→ Fresh Reader re-certifies the new Manuscript
```

Runtime / reference pipeline 不再自动 `review → revise → review → revise → ... until PASS`。

如果新的 Reader 再次阻塞，Host 应暴露当前 failure，而不是默认继续 critic-driven hill climbing。

v0.6 不新增 `review_round`、`quality_score` 或新的 report lifecycle 来控制这一点。

---

## 14. Research Integrity 保持独立且严格

Integrity 继续验证 substantive claim strength、scope、causality / mechanism、exact quantitative claims、load-bearing equations / mathematics、benchmark comparability、SOTA、significance、generalization、robustness / efficiency dimensions、resource budgets、absolute / time-sensitive claims、citation-to-evidence fidelity，以及 Research State 外的新 substantive conclusion。

Integrity 优先关注：

> **load-bearing substantive claims 与 high-risk claims。**

它不负责 prose quality、information architecture、paragraph rhythm、AI-like style 或 material economy。

结果仍为：

```text
PASS
REVISE_DELIVERY(target=MANUSCRIPT | BRIEF)
REOPEN_RESEARCH
```

---

## 15. `REPORT_QUALITY_STANDARD.md` 退出 Production authority

v0.6 不再向 Constructor 或 Reader加载完整 `REPORT_QUALITY_STANDARD.md`。

其中有价值的概念可以保留为 design history、E2E diagnostics 或 architecture analysis reference，但它不再作为 production rubric。

Production 不再建立统一的 Cognitive Continuity ontology、Material Economy ontology、Professional Chinese ontology、Global Closure ontology 或 Report Quality score。

核心原因：

> **没有任何 semantic role 负责全局优化 report quality。**

最终质量来自：

```text
editorial judgment
+
strong realization
+
reader acceptance
+
research fidelity
```

而不是由一个统一 quality function 驱动。

---

## 16. Runtime：保留机械骨架，只删除语义过度控制

v0.6 保留：

```text
DeliveryBasis binding
Report session persistence
brief_digest
manuscript_digest
ReaderPass
IntegrityPass
pending_action
semantic-change invalidation
fail-closed schema migration
deterministic citation renderer
citation eligibility
canonical link resolution
internal-ref leakage checks
Markdown / LaTeX mechanical checks
publication authorization
```

v0.6 不为理论纯度重构 `pending_action`、ReaderPass / IntegrityPass persistence、stage labels 或 digest placement。

原则：

> **优先删除影响 Agent semantic freedom 的控制；不重写已经便宜、可靠、容易理解的 boring runtime machinery。**

---

## 17. 删除 exact outline fidelity

v0.6 删除 Brief 与 Manuscript reader-visible outline 的机械一一对应。

Python 不再要求：

```text
H1 == Brief title
H2/H3 text == Brief section title
heading order == Brief section order
heading depth == Brief outline_depth
```

Brief 本身不再拥有 visible outline。

Presentation Runtime 只检查真正确定性的机械问题，例如：

```text
non-empty manuscript
citation-token integrity
unsupported deterministic token
internal ref leakage
fenced block / math delimiter integrity
bibliography ownership
formal evidence eligibility
```

标题与章节结构属于 Authoring realization，并由 Reader验收最终效果。

---

## 18. 修复 Blind → Phase 2 staged hole

v0.5 staged runtime 允许：

```text
submit Blind Read
→ 未完成 Phase 2
→ Host 直接提交新 Manuscript
```

这使冻结的 Blind observation 可以被绕过。

v0.6 加入简单 invariant：

```text
current Blind Read exists
AND current Reader Review is absent

→ semantic mutation is blocked
→ submit-reader-review must complete Phase 2 first
```

不新增 persisted stage 或 lifecycle。

---

## 19. Report pipeline 不再编码 “until PASS”

production authority 继续是 staged `CertifiedReportDelivery`。

reference / compatibility `ReportPipeline` 不得继续把 `max_reader_rounds` 与 `_review_until_reader_pass()` 作为 canonical semantics。

v0.6 可选择：

1. 删除 `ReportPipeline` 的 production/reference authority；或
2. 将其降级为一次性 action adapter，不再拥有自动 convergence loop。

具体实现选择不改变 ADR authority boundary。

---

## 20. Citation 与 Presentation 继续确定性处理

v0.6 不把 style simplification 扩散到 citation safety。

继续由 Python处理 structured citation token validation、optional paper navigation、formal evidence eligibility、bibliography generation、canonical URL resolution、malformed token rejection、internal stable ref leakage，以及可靠的 Markdown / LaTeX structural defects。

Python 不做 method-name NLP、claim support semantic judgment、prose correction 或 semantic auto-fix。

---

## 21. Guide ownership

### `REPORT_CONSTRUCTION_GUIDE.md`

收缩为很短的 Constructor Charter，只说明：

* Promise / Frame / Arc / Focus；
* reader attention；
* semantic ceiling；
* Research escalation。

### `REPORT_WRITING_GUIDE.md`

收缩为很短的 Authoring Charter，只说明：

* faithful realization；
* local implementation freedom；
* read-only Research support；
* no new Research judgment；
* `BriefInsufficient`。

### `REPORT_REVIEW_GUIDE.md`

收缩为很短的 Reader Charter，只说明：

* Blind Reading；
* true blocker；
* no optimization；
* Phase 2 compatibility / attribution。

### `RESEARCH_INTEGRITY_GUIDE.md`

继续相对详细，只负责 substantive research fidelity。

### `REPORT_QUALITY_STANDARD.md`

不进入 production prompt path。

## 22. 不变量

v0.6 的核心不变量：

```text
1. Research State is the only research authority.

2. Completion remains the authority that permits complete Delivery.

3. Report Brief is the only report-semantic middle layer.

4. Report Brief expresses editorial intent, not manuscript structure or material plan.

5. Constructor owns Promise / Frame / Arc / Focus.

6. Authoring owns visible realization and may use targeted read-only Research support.

7. Authoring cannot create new Research judgments.

8. Fresh Reader measures acceptance; it does not optimize the report.

9. Reader can route only MANUSCRIPT or BRIEF.

10. Research Integrity independently verifies substantive fidelity and may reopen Research.

11. Semantic changes invalidate downstream certifications bound to the changed artifact.

12. Blind Read must complete Phase 2 before it can be discarded by semantic mutation.

13. Reader PASS is required before Integrity.

14. Matching Reader PASS and Integrity PASS are required before publication.

15. Citation / rendering mechanics remain deterministic Python responsibilities.

16. No automatic Reviewer→Reviser convergence loop is part of the canonical Delivery path.
```

v0.6 不增加：

```text
Style Reviewer
Naturalness Reviewer
Polish Agent
Material Planner
Evidence Consumption Plan
Detailed section IR
Editorial Score
```

这些规则会把观察到的症状固化为新的 Harness。

## 24. Migration

Report Brief 与 Reader result schema 发生 breaking change。

Runtime 应：

```text
schema_version bump
old report_session
→ fail closed
→ rebuild Report Brief under v0.6
```

不自动把 v0.5 的 `sections / semantic_moves / material / reader-visible obligations` 迁移成 v0.6 Brief。

原因：

> 自动迁移会把旧的过度 specification 重新带入新语义。

Research State 与 DeliveryBasis 不需要重建，只重建 Delivery work products。

---

## 25. v0.6 成功标准

实现后的 E2E 不以“更少字”作为成功标准。

主要观察：

1. Brief 是否明显从 manuscript specification 退回 editorial intent；
2. Writer 是否仍能获得足够 evidence 形成严谨正文；
3. 最终报告是否不再默认 method / metric / taxonomy-heavy；
4. exact formulas / numbers 是否只在真正改变理解时出现；
5. Writer 是否拥有真实的 title / outline / section freedom；
6. Reader 是否主要产生 PASS 或少量 root blocker，而不是大量 friction；
7. 是否消失 rev1 → revN 式 Reader hill-climbing；
8. Integrity 是否仍能抓住数字、scope、causality、mechanism、citation 等实质错误；
9. deterministic citation / publication safety 是否无回归；
10. 系统是否在没有新增 Agent / Gate / Score 的前提下改善最终成品。

---

## 26. 最终原则

v0.6 的设计目标不是更少代码本身。

而是：

> **让每一项控制只存在于最有资格拥有它的地方。**

Research 保留丰富知识。

Constructor 只做编辑取舍。

Authoring 真正写文章。

Reader 只验收读者结果。

Integrity 只核验重要研究真相。

Python 只守住没人有合理理由绕过的机械边界。

可以概括为：

> **Deep Research → Lean Editorial Design → Strong Authoring → Light Reader → Strict Integrity.**
