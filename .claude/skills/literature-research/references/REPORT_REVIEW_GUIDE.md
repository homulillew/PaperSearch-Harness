# Report Review Guide

> 版本：v0.3  
> 适用角色：Report Reviewer / Reader Gate  
> 目标：验证最终稿是否真正作为面向目标读者的认知载体成立  
> 不负责：研究完成性判断、Research State 修改、Primary Evidence 最终核验、事实修复

---

## 1. Purpose and Boundary｜目的与边界

Report Reviewer 回答的是：

> **这篇报告作为文章是否成立？目标读者能否仅凭正文形成连续、稳定、可复述的领域理解？**

它不回答：

> **这些研究判断最终是否真的被 Research State 与 Primary Evidence 支持？**

后者属于 Research Integrity Review。

因此 Reader Gate 与 Research Integrity Gate 必须保持独立。

Reader Gate 主要检查：

- 读者实际形成了什么理解；
- 认知路径是否连续；
- 主要判断是否被文章真正建立；
- 材料是否服务于论证；
- 报告是否存在认知跳步、认知重启、认知债务或论证孤岛；
- 文章实际呈现的认知结构是否与 Report Brief 一致；
- 问题究竟属于 Manuscript，还是属于 Report Brief / Report Construction。

Reader Gate 不负责：

- 判断 Research State 是否完整；
- 判断某项 Finding 是否应被修改；
- 根据论文重新形成新的领域判断；
- 调整 Approach Family；
- 将用户或 Reviewer 的研究意见直接写入 Research State；
- 通过自行重新研究来修正文稿。

---

## 2. Review Principle｜审查原则

Reader Reviewer 不是“编辑老师”，也不是“风格打分器”。

它的核心任务不是问：

> “我觉得这篇文章写得好吗？”

而是问：

> **“作为第一次读者，我实际建立了什么理解？哪里无法继续建立理解？为什么？”**

因此 Reviewer 应优先报告：

```text
具体位置
+
具体理解失败
+
该失败影响哪个主要判断或认知路径
+
最早有资格修复它的层
```

而不是：

```text
结构比较清晰
语言较为流畅
可以进一步优化表达
专业性 8/10
可读性 7/10
```

本 Guide 不使用统一质量分数。

---

## 3. Two-Phase Cold Reading｜两阶段冷读

每个新 Manuscript 必须由新的 Reviewer instance 进行审查。

任何 Manuscript 修改都会使旧 Reader PASS 失效。

新的 Reviewer 必须重新从 Phase 1 开始。

审查分两阶段：

```text
Phase 1 — Blind Read
不看 Report Brief
→ 重建读者实际获得的认知结构

Phase 2 — Brief Check
读取 Report Brief
→ 比较“设计的认知路径”和“实际读出的认知路径”
```

两阶段不能倒置。

如果 Reviewer 一开始就读取 Brief，它会知道作者原本想表达什么，并可能自动替文章补全正文缺失的逻辑。

这会削弱 first-time-reader validation。

# Phase 1 — Blind Read

## 4. Blind Read Inputs｜盲读输入

Phase 1 只接收：

```text
Deliverable description
Audience
Report Quality Standard
Report Review Guide
Manuscript
```

Phase 1 不接收 Report Writing Guide。

`Audience` 可以来自当前 Report Brief 的窄投影，但只能暴露目标读者描述本身；不得因此暴露 Brief 的 `reader_takeaway`、`narrative_logic`、section 设计、material 或 `intentional_omissions`。

Phase 1 也不接收 Research State、Primary Evidence、Report Constructor / Writer notes 或前一轮 Reviewer 的推理记录。

原因是 Reader Gate 审查的是**成品实际产生的读者理解**，而不是 Writer 是否遵守了生成指导。Writer 接受过什么写作建议、研究者原本知道什么，都不应帮助 Reviewer 解释正文中本身没有建立起来的关系。

不接收：

```text
Report Brief
Research State
Paper Analysis
Approach Family
Finding
Open Problem
Primary Source
Constructor notes
Writer notes
previous Reviewer reasoning
```

必要时可以知道目标受众和交付要求，因为真实读者通常知道自己为什么在读这份报告。

但 Reviewer 不应获得作者隐藏的认知设计。

---

## 5. First-Pass Reading Discipline｜第一次阅读纪律

Reviewer 应尽可能模拟一个真实专业读者，而不是逐句寻找问题。

第一次阅读时：

1. 正常从头到尾阅读；
2. 不提前构造修订方案；
3. 不因为自己“猜到了作者想表达什么”而自动补全缺失关系；
4. 标记第一次明显需要回读的位置；
5. 标记第一次不知道“这段为什么在这里”的位置；
6. 标记第一次出现无法解释其作用的数字、术语或论文；
7. 标记章节切换时是否需要重新建立新的局部模型。

Blind Read 的重点不是尽量发现更多问题，而是观察：

> **真实阅读状态如何变化。**

### 5.1 不得用 Reviewer 自身知识替正文补桥

Reviewer 能够推断出某个缺失关系，不代表文章已经把该关系传递给读者。

当重要关系主要依赖以下信息才能被补全时：

- Reviewer 自身领域知识；
- 对作者意图的猜测；
- 后文才出现的信息；
- Report Brief 中的设计说明；
- 对 Research State 的了解；

Reviewer 应明确区分：

```text
文本已经建立的关系
vs
Reviewer 自行补出的关系
```

不得因为 Reviewer 最终“猜对了”，就免除认知跳步。

核心原则：

> **Reviewer 能推出来，不等于读者被文章带到了那里。**

---

## 6. Core Reconstruction Test｜核心认识重建

完成第一次阅读后，不回看 Report Brief，Reviewer 应回答：

### 6.1 全文核心认识

用不超过 3 句话回答：

> **这篇报告最终告诉了我什么？**

如果 Reviewer 只能说：

> “它介绍了 A、B、C、D 几种方法。”

通常说明报告可能只有覆盖，没有形成更高层认识。

### 6.2 领域心智模型

回答：

> **读完后，我现在如何理解这个领域？**

应尽量重建：

- 核心问题；
- 主要约束；
- 主要技术路线为什么出现；
- 各路线真正改变什么；
- 路线之间最重要的差异；
- 当前证据支持哪些总体判断；
- 仍然有哪些未知。

### 6.3 稳定比较坐标

回答：

> **报告实际使用哪些稳定维度比较不同路线？**

例如：

```text
改变了什么成本
收益从哪里产生
代价转移到哪里
适用条件
证据边界
部署要求
```

如果每个章节使用完全不同的比较方式，Reviewer 应记录为潜在认知结构失败。

---

## 7. Reverse Outline｜反向提纲

Blind Read 后，Reviewer 应基于 Manuscript 自身重建一份简短反向提纲。

不是复述目录。

而是回答：

```text
全文中心判断
  ↓
主要子判断 A
  ↓
A 是如何被建立的
  ↓
主要子判断 B
  ↓
为什么 B 必须在 A 之后出现
  ↓
跨路线综合判断
  ↓
最终结论 / 开放问题
```

每个主要章节应尝试写成：

```text
这一部分实际完成的认知任务：
这一部分让读者新增的认识：
这一部分如何依赖前文：
这一部分如何支持后文：
```

如果 Reviewer 无法填写“如何依赖前文”或“如何支持后文”，该章节可能形成认知重启或论证孤岛。

---

## 8. Cognitive Continuity Checks｜认知连续性检查

### 8.1 认知跳步

检查：

> 是否存在从 A 直接到 C，但理解 C 所需的 B 尚未建立？

常见表现：

- 结论突然加强；
- 比较突然切换维度；
- 从实验结果直接跳到部署结论；
- 从局部论文结果直接跳到领域判断；
- 从机制描述直接跳到优劣排序。

记录时不要只写：

> “逻辑衔接不够。”

应写成：

```text
位置：
从“X”直接进入“Y”。

读者缺失的中间关系：
需要先理解 Z，才能合理理解 Y。

影响：
当前结论要求读者自行补足关键推理。
```

### 8.2 认知重启

检查：

> 新章节是否继承前文已经建立的模型？

典型表现：

```text
每节重新介绍背景
每节重新定义问题
每节重新建立比较标准
每节都像一篇独立小综述
```

Reviewer 应判断：

> 前一节的理解是否降低了后一节的理解成本？

如果没有，且多个主要章节反复如此，则属于全局结构问题。

### 8.3 认知债务

检查：

> 报告是否让读者长期记住大量尚未解释其意义的信息？

重点关注：

- 连续方法名；
- 密集数字；
- benchmark 名称；
- 缩写；
- 尚未解释的分类；
- 尚未消费的对比结果。

问题不在于信息数量本身，而在于：

> **这些信息是否很快获得认知归宿。**

### 8.4 论证孤岛

检查：

> 是否存在正确但与前后主论证没有连接的材料？

Reviewer 可使用删除测试：

> 如果删除这一段，全文主要认知链是否几乎不变？

如果答案是“是”，则该段可能只是信息展示，而不是必要论证。

---

## 9. Argument Completeness Checks｜论证完整性检查

对于全文的重要判断，Reviewer 应检查读者能否找到：

```text
判断
机制 / 原因
证据
条件 / 限制
含义
```

不要求机械五件套。

重点是：

> **读者是否知道为什么应该接受这个判断。**

### 9.1 判断是否清楚

检查：

- 本段到底在判断什么；
- 判断是否隐藏在大量背景之后；
- 判断是否频繁换词导致边界漂移。

### 9.2 机制是否足够

检查：

> 文章有没有解释为什么会发生这种结果？

如果报告只有：

```text
方法 → 数字
```

没有解释机制，读者可能获得事实但没有形成领域理解。

### 9.3 证据是否被解释

检查：

- 数字为什么出现；
- 论文为什么被引用；
- 结果是否支持当前判断；
- 是否存在明显不可比结果被视觉并列。

### 9.4 限制是否进入主要判断

检查：

> 条件和限制是否真正改变读者对结论的理解？

如果限制只在段尾弱化成一句：

> “当然仍存在一定局限。”

但正文主要判断仍表现成普遍成立，则文章论证质量不足。

### 9.5 含义是否被建立

检查：

> 读者知道这个结果对路线关系、部署选择、领域结构或后文意味着什么吗？

如果大量段落停留在：

> “论文做了什么。”

报告可能仍然没有完成 synthesis。

---

## 10. Material Economy Checks｜材料经济性检查

Reviewer 应主动寻找：

> **正确但没有必要认知功能的材料。**

### 10.1 材料功能测试

对重要材料问：

```text
它是在建立认识？
还是在区分路线？
还是在校准判断？
```

如果都不是，应检查是否可以省略。

### 10.2 重复支持测试

当一个判断已经被充分建立后，检查：

> 后续同类论文和数字有没有增加新认知？

如果只是重复证明相同结论，应考虑是否形成材料堆叠。

### 10.3 数字消费测试

每个重要数字出现后，Reviewer 应能回答：

> **这个数字在当前论证中完成了什么任务？**

如果不能，则可能是认知债务或材料冗余。

### 10.4 论文名删除测试

如果删除论文名后，一段文字失去全部组织结构，则该段可能仍然是 paper-by-paper summary。

---

## 11. Information Presentation Checks｜信息呈现检查

Reviewer 不要求固定使用 prose、list、table 或 figure。

只检查：

> **当前呈现是否降低理解成本。**

### 11.1 连续推理是否被拆碎

如果明显存在：

- 因果；
- 递进；
- 条件；
- 推导；

却被机械拆成大量 bullet，读者可能需要自行重建逻辑。

### 11.2 平行信息是否难以扫描

如果多个真正独立的条件或风险被反复写成长段，可能导致重复。

### 11.3 表格是否存在共同坐标

检查：

- 每列是否代表稳定维度；
- 对象是否真的可比较；
- 表格是否只是论文列表换形式；
- 正文是否逐格复述。

### 11.4 标题是否承担认知导航

标题不需要全部写成结论句。

但读者扫标题时应大致知道：

> 文章在推进什么问题。

如果标题只是：

```text
方法 A
方法 B
方法 C
```

Reviewer 应检查全文是否实际上复刻 Research taxonomy。

---

## 12. Professional Chinese Checks｜专业中文检查

Reviewer 只处理**实质影响理解**的语言问题。

不要把 Review Loop 变成无限润色。

重点检查：

- 句法是否持续遮蔽技术关系；
- 主语和动作是否长期不明确；
- 抽象名词是否替代具体机制；
- 同一个判断是否反复换词重述；
- 模板化连接词是否大量替代真实逻辑；
- 段落是否异常均质；
- AI 生成节奏是否显著干扰连续阅读。

单个：

```text
值得注意的是
总体来看
在此基础上
```

不构成 blocker。

只有当这些模式反复出现并增加认知成本时，才应报告。

---

## 13. Global Closure Checks｜全文闭合检查

完成 Blind Read 后，Reviewer 应检查：

### 13.1 结论是否来自正文

结论是否引入：

- 新分类；
- 新判断；
- 新因果；
- 新比较坐标。

如果有，检查正文是否已经建立。

### 13.2 分类体系是否漂移

例如：

```text
正文：五条路线
结论：四个范式
```

不一定错误。

但必须解释二者关系。

### 13.3 开放问题是否自然产生

检查：

> 最后的开放问题是否来自前文已经建立的限制和证据缺口？

如果像额外附上的“未来方向”，则全文闭合不足。

### 13.4 文章为何在这里结束

Reviewer 应能够回答：

> **主要报告承诺是否已经闭合？**

而不是：

> “材料似乎写完了。”

---

## 13.5 Phase 1 只诊断，不归因

Blind Read 阶段只回答：

> **哪里发生了真实理解失败？**

不要在这一阶段决定：

```text
MANUSCRIPT
BRIEF
RESEARCH
```

等修复目标。

原因是提前猜测故障层会反向影响 Reviewer 对正文的阅读。

正确顺序：

```text
Phase 1
发现并描述理解失败
        ↓
冻结 Blind Read 结果
        ↓
Phase 2
读取 Report Brief
        ↓
比较设计认知与实际认知
        ↓
再进行故障归因
```

即：

> **先诊断，再归因。**

# Phase 2 — Brief Check

## 14. Brief Check Inputs｜蓝图核对输入

Phase 2 在完成 Blind Read 记录后才接收：

```text
Report Brief
```

Reviewer 不应修改 Phase 1 的原始阅读结论来迎合 Brief。

Phase 1 回答：

> 实际读到了什么？

Phase 2 回答：

> 这和设计目标有什么差异？

---

## 15. Designed vs Received Understanding｜设计认知与实际认知对比

Reviewer 应比较：

```text
Brief reader_takeaway
vs
Blind Read 实际复述结果
```

以及：

```text
Brief narrative_logic / argument_flow
vs
Blind Read reverse outline
```

重点找：

### 15.1 设计认识没有进入正文

例如 Brief 设计：

> “不同路线实际在改变不同成本变量，因此不能脱离部署条件统一排序。”

但 Blind Reader 只得到：

> “有八种方法，各自都有优缺点。”

这属于严重认知传递失败。

### 15.2 正文弱化了 Brief

Brief 中存在重要限定，但正文为了顺滑而删除。

### 15.3 正文加入了 Brief 未授权的重要判断

这可能是 Writer 越界。

最终是否研究上错误，由 Integrity 判断。

Reader Reviewer 只指出：

> 正文出现了蓝图之外的重要认知。

### 15.4 Brief 本身设计不足

如果：

```text
Manuscript 忠实执行 Brief
+
Blind Read 仍然无法形成连续理解
```

说明问题可能不在 Writer。

例如：

- Brief 本身把八条路线设计成八个孤立章节；
- Brief 缺少稳定比较坐标；
- Brief 没有安排跨路线 synthesis；
- Brief 的 argument_flow 本身存在跳步。

此时应路由到 Report Construction。

---

## 16. Fault Attribution｜故障归因

Reviewer 必须尽量定位**最早错误层**。

### 16.1 Manuscript Fault → Reviser

典型：

- 一个关键过渡没有写出来；
- 某段同时承担多个认知任务；
- 一个限制条件被正文弱化；
- 表格与正文重复；
- 某段语言明显难读；
- Brief 已明确比较坐标，但 Writer 没有贯彻。

路由：

```text
MANUSCRIPT
→ Reviser
```

### 16.2 Brief Fault → Report Constructor

典型：

- 全文没有稳定比较框架；
- 章节设计导致持续认知重启；
- 关键 synthesis 没有被设计；
- Brief material 本身不足以建立目标判断；
- argument_flow 本身存在认知跳步；
- intentional_omissions 错误导致关键认知环节缺失。

路由：

```text
BRIEF
→ Report Constructor
```

### 16.3 疑似研究层问题 → 升级确认

Reader Reviewer 通常不负责确认 Research Fault。

但如果文章暴露明显研究层问题，例如：

> “要完成当前交付，必须形成一个 Research State 尚不存在的领域判断。”

可以标记：

```text
POSSIBLE_RESEARCH_ISSUE
```

这不是 `Research Fault` 的最终裁决，也不意味着自动修改 Research State 或自动进入 RESEARCH。

最终是否需要回到 RESEARCH，应由具有相应研究判断权限的阶段确认。

Reader Reviewer 只有**发现 / 升级权**，没有研究裁决权，也不应自行研究来解决。

---

## 17. Blocking Issue Definition｜阻塞问题定义

Blocking Issue 必须满足：

> **如果不修复，它会实质性破坏目标读者对主要报告承诺的理解。**

常见 blocker：

- 无法复述全文主要认识；
- 缺少稳定比较坐标；
- 关键认知跳步；
- 多个主要章节持续认知重启；
- 主要论证链断裂；
- 大量关键材料无论证功能；
- Brief 与正文认知结构显著不一致；
- 结论没有由正文建立；
- 语言问题持续阻碍理解。

通常不应成为 blocker：

- Reviewer 个人更喜欢另一种措辞；
- 单个句子可以更漂亮；
- 单个连接词稍显模板；
- 不影响认知链的轻微篇幅问题；
- 纯审美性的标题偏好。

---

## 17.5 Root-Cause Consolidation｜根因合并

Reviewer 不应把同一个上游认知缺陷拆成大量重复 Blocking Issues。

如果多个症状：

- 具有相同的认知根因；
- 指向同一个最早错误层；
- 可以通过同一次结构性修复共同消除；

则应优先合并为一个 Blocking Issue。

例如：

```text
路线之间显得扁平
+
比较框架出现过晚
+
多个章节存在认知重启
+
同一工作被放入多个平级类别
```

如果这些现象都来自：

> “统一领域模型没有在正文中持续实现”

则应报告一个根因级 blocker，而不是四个独立 blocker。

目标是：

> **抓根因，不抓噪声。**

这可以降低 Reviewer ↔ Reviser 因重复、细碎和审美性意见产生的活锁风险。

---

## 18. Blocking Issue Format｜问题输出格式

每个 Blocking Issue 建议至少包含：

```text
location
problem
reader_effect
why_blocking
repair_target
```

可选：

```text
brief_ref
related_takeaway
suggested_repair_direction
```

示例：

```text
location:
“量化路线”结尾到“缓存淘汰”开头

problem:
正文从“量化降低单元素存储成本”直接切换到
“缓存淘汰通过减少 token 数降低总缓存”，
没有先建立“总缓存成本由单元素成本 × 保留状态数量共同决定”。

reader_effect:
读者必须自行推断两条路线为什么属于同一个比较框架。

why_blocking:
这一缺失导致后续多路线比较没有统一坐标，
影响全文核心认知模型。

repair_target:
MANUSCRIPT
```

如果 Brief 本身没有设计这个比较框架：

```text
repair_target:
BRIEF
```

---

## 19. PASS Criteria｜通过条件

Reader Gate PASS 不表示：

> “这篇文章完美。”

PASS 表示：

> **在目标读者假设下，没有剩余足以破坏主要理解的 Blocking Issue。**

具体意味着：

- 全文核心认识可以被复述；
- 主要认知路径连续；
- 关键比较坐标可重建；
- 没有严重认知跳步；
- 没有系统性认知重启；
- 主要论证能够被追踪；
- 重要材料具有明确功能；
- 结论与正文闭合；
- Blind Read 实际获得的认知结构与 Brief 基本一致；
- 剩余问题属于非阻塞性的局部优化。

停止条件：

```text
Blocking Issues = ()
```

不是：

```text
quality_score >= threshold
review_round >= N
Reviewer “总体满意”
```

---

## 19.5 Reader PASS 绑定具体 Brief / Manuscript 版本

Reader Gate PASS 认证的是一个具体组合：

```text
Report Brief version
+
Manuscript version
```

因此：

```text
Manuscript 修改
→ 旧 Reader PASS 失效

Report Brief 修改
→ 旧 Reader PASS 失效
```

Runtime 不判断修改是否“足够小”。

原则是：

> **Reader PASS 属于具体版本产物，不属于流程阶段。**

Phase 1 的 Blind Read 记录也必须绑定它实际阅读的 Manuscript 版本，并在 Phase 2 暴露 Brief 前冻结。

---

## 20. Fresh Review Invariant｜新鲜审查不变量

任何 Manuscript 修改后：

```text
old Reader PASS
→ invalid
```

新的 Manuscript 必须：

```text
NEW Reviewer
→ Phase 1 Blind Read
→ Phase 2 Brief Check
```

不能让同一 Reviewer 直接确认：

> “我看到你按我说的改了，所以 PASS。”

因为它已经知道作者意图和前一轮缺陷，无法再模拟真正第一次阅读。

---

## 21. Human Calibration｜人类校准

Reader Gate 是机器质量保障，不是人类接受的替代。

如果出现：

```text
AI Reader → PASS
Human Reader → 明确理解失败
```

应把人类反馈视为重要校准信号。

后续应判断：

- Quality Standard 是否遗漏失败类型；
- Review Guide 是否没有正确执行已有标准；
- 目标读者假设是否错误；
- Blind Reader 是否过度依赖模型自身推断能力；
- Report Brief 是否错误估计真实读者前置知识。

AI PASS 不能覆盖真实人类的明确负面阅读反馈。

---

# Reviewer Minimal Checklist｜最小审查清单

Phase 1 必须至少回答：

```text
1. 全文核心认识是什么？
2. 我实际形成了什么领域模型？
3. 主要比较坐标是什么？
4. 反向提纲是什么？
5. 哪里存在认知跳步？
6. 哪里存在认知重启？
7. 哪里存在认知债务或论证孤岛？
8. 重要材料是否都有明确作用？
9. 主要判断是否有可追踪论证？
10. 结论是否与正文闭合？
```

Phase 2 必须至少回答：

```text
11. Blind Read 得到的认识是否与 Brief reader_takeaway 一致？
12. 实际反向提纲是否与 Brief argument_flow 一致？
13. 是否遗漏、弱化或新增重要认知？
14. 多个症状是否应合并为同一根因级 Blocking Issue？
15. 最早错误层属于 Manuscript、Brief 还是需要进一步升级确认？
16. 是否仍存在 Blocking Issue？
```

---

# Final Principle｜最终原则

Report Reviewer 的职责不是替作者把文章改得更漂亮。

它的职责是验证：

> **一个不知道作者内部意图的真实专业读者，是否能够仅凭最终文章，沿着连续而不过度压缩的认知路径，形成 Report Brief 预期的领域理解。**

因此 Reader Gate 的核心不是：

> “文章看起来专业吗？”

而是：

> **“文章是否真的把正确的认知结构送进了读者脑中？”**
