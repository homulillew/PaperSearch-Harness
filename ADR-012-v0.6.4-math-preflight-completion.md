# ADR-012 v0.6.4 — Math Rendering Preflight: Completion Report

## Summary

Implemented a real **math rendering preflight** for report manuscripts. The
invariant: *every mathematical expression in a report manuscript must be
accepted by the target math renderer before the manuscript can proceed to
Reader certification or publication.* This is **only** mechanical
renderability — not semantic validation, not formula fidelity, not style
linting.

The observed E2E failure — `$A^_tree=A^_Intra+A^_Inter$` passing the old
delimiter-boundary check — is now rejected before the Reader, with MathJax's
exact error ("Missing open brace for superscript").

## What was built

- **`runtime/.../math/validate.js`** — a small Node validator. Reads a JSON
  array of TeX strings from stdin (one batch), loads MathJax **once**
  (`liteAdaptor` + `SVG` + `TeX({packages: AllPackages})`), and writes a JSON
  array of `{ok, error}` results to stdout. Rejection is detected via the
  `data-mjx-error="..."` attribute MathJax emits on `merror` nodes, or by
  catching thrown errors.
- **`runtime/.../math/package.json`** — declares the `mathjax-full@3.2.1`
  dependency. `npm install` provisions the renderer next to the script,
  mirroring the Python `.venv` pattern.
- **`runtime/.../math_preflight.py`** — the thin Python adapter. Extracts the
  TeX content of `$…$`, `$$…$$`, `\(…\)`, `\[…]` spans (ignoring fenced code
  blocks and inline code spans), short-circuits with no Node call when there
  is no math, and otherwise makes **one** batch subprocess call to the
  validator. Fail-closed via `MathRendererUnavailable` when the renderer is
  absent but math is present.
- **`citations.py`** — wired `_validate_math_renderability()` into
  `DeterministicCitationRenderer.audit()`, immediately after the existing
  structural check and before citation resolution / Reader review. Reuses the
  existing `CitationValidationError` (no new public error type).

## Integration path (confirmed under Node 26)

`mathjax-full@3.2.1`'s `node-main` bootstrap is broken under Node 26
(`eval("require")` fails in stricter ESM-in-CJS resolution). The working path:
`require()` the individual `mathjax-full/js/*.js` **CommonJS source modules
directly**, bypassing the bootstrap. `liteAdaptor` needs no DOM; `AllPackages`
loads AMS environments so valid matrices/cases/align are not false-rejected.

## MathJax behavior (empirically verified, then pinned)

| Expression | Verdict |
|---|---|
| `A^_tree=A^_Intra+A^_Inter` (E2E failure) | **rejected** — "Missing open brace for superscript" |
| `x^`, `x_` | **rejected** — "Missing superscript or subscript argument" |
| `\frac{a}` | **rejected** — "Missing argument for \frac" |
| `\frac{a}{b` | **rejected** — "Missing close brace" |
| `\sqrt` (no arg) | **rejected** — "Missing argument for \sqrt" |
| `R^(\lambda)`, `x^10`, `A_tree` | **accepted** (borderline but valid — NOT rejected) |
| `R^{(\lambda)}`, `A_i^E`, `\frac{a}{b}`, matrix/cases/align | accepted |

This matches the spec: reject structurally broken TeX; **do not** reject
syntactically valid borderline notation.
