# ADR-012 v0.6.4 — Math Rendering Preflight: Completion Report

## Summary

Implemented a real **math rendering preflight** for report manuscripts. The
invariant: *every supported mathematical expression in a report manuscript must
be accepted by the configured MathJax renderer before the manuscript can
proceed to Reader certification or publication.* This is **only** mechanical
renderability — not semantic validation, not formula fidelity, not style
linting.

The supported authoring surface is intentionally small and explicit:
`$...$`, `$$...$$`, `\(...\)`, `\[...\]`. Fenced code blocks and inline code
spans are verbatim and excluded from extraction. No other Markdown math
notation is claimed to be supported.

The observed E2E failure — `$A^_tree=A^_Intra+A^_Inter$` passing the old
delimiter-boundary check — is now rejected before the Reader, with MathJax's
exact error ("Missing open brace for superscript").

## What was built

- **`runtime/.../math/validate.js`** — a small Node validator. Reads a JSON
  array of TeX strings from stdin (one batch), loads MathJax **once**
  (`liteAdaptor` + `SVG` + `TeX({packages: AllPackages})`), and writes a JSON
  array of `{ok, error}` results to stdout. Rejection is detected via the
  `data-mjx-error="..."` attribute MathJax emits on `merror` nodes, or by
  catching thrown errors.
- **`runtime/.../math/package.json`** — declares the `mathjax-full@3.2.1`
  dependency. `npm install` provisions the renderer next to the script,
  mirroring the Python `.venv` pattern.
- **`runtime/.../math_preflight.py`** — the thin Python adapter. Extracts the
  TeX content of the supported spans (`$…$`, `$$…$$`, `\(…\)`, `\[…]`;
  ignoring fenced code blocks and inline code spans), short-circuits with no
  Node call when there is no supported math, and otherwise makes **one** batch
  subprocess call to the validator. Before consuming the response it validates
  the full result contract (N expressions in → exactly N structurally valid
  results out; each a dict with a bool `ok`; every rejection carries a
  non-empty error) and fails closed via `MathRendererUnavailable` on any
  violation. Fail-closed the same way when the renderer is absent but math is
  present.
- **`citations.py`** — wired `_validate_math_renderability()` into
  `DeterministicCitationRenderer.audit()`, immediately after the existing
  structural check and before citation resolution / Reader review. Reuses the
  existing `CitationValidationError` (no new public error type).

## Integration path (confirmed under Node 26)

`mathjax-full@3.2.1`'s `node-main` bootstrap is broken under Node 26
(`eval("require")` fails in stricter ESM-in-CJS resolution). The working path:
`require()` the individual `mathjax-full/js/*.js` **CommonJS source modules
directly**, bypassing the bootstrap. `liteAdaptor` needs no DOM; `AllPackages`
loads AMS environments so valid matrices/cases/align are not false-rejected.

## MathJax behavior (empirically verified, then pinned)

| Expression | Verdict |
|---|---|
| `A^_tree=A^_Intra+A^_Inter` (E2E failure) | **rejected** — "Missing open brace for superscript" |
| `x^`, `x_` | **rejected** — "Missing superscript or subscript argument" |
| `\frac{a}` | **rejected** — "Missing argument for \frac" |
| `\frac{a}{b` | **rejected** — "Missing close brace" |
| `\sqrt` (no arg) | **rejected** — "Missing argument for \sqrt" |
| `R^(\lambda)`, `x^10`, `A_tree` | **accepted** (borderline but valid — NOT rejected) |
| `R^{(\lambda)}`, `A_i^E`, `\frac{a}{b}`, matrix/cases/align | accepted |

This matches the spec: reject structurally broken TeX; **do not** reject
syntactically valid borderline notation.

## Robustness patch (v0.6.4 post-completion)

Three gaps surfaced during review of the initial implementation. All three are
closed without touching the protected surface (ReportBrief, Constructor, Reader,
Integrity, Research State, Completion, Deep Reading, citation semantics,
certification, report lifecycle) and without adding any semantic layer, score,
gate, or persisted state.

1. **Strict result-protocol validation.** The initial adapter consumed the
   renderer response with `zip(expressions, results)`, which silently stops at
   the shorter sequence. A truncated but valid-JSON payload (fewer results
   than expressions, or results missing the `ok` flag) could leave expressions
   unchecked. The adapter now validates the full response contract *before*
   consuming any result: `results` must be a list of length `len(expressions)`;
   every entry must be a dict with a bool `ok`; every rejection (`ok: false`)
   must carry a non-empty `error` string. Any violation raises
   `MathRendererUnavailable` with "configured MathJax renderer returned an
   invalid result payload; renderability cannot be certified". The core rule:
   N expressions in → exactly N structurally valid results out, or fail closed.

2. **Explicit, intentionally small supported surface.** The module docstring
   and the Writing Guide now name the supported math forms explicitly
   (`$...$`, `$$...$$`, `\(...\)`, `\[...\]`) and state that fenced code blocks
   and inline code spans are verbatim and excluded. The adapter no longer
   claims to validate "every GitHub Markdown math form"; it validates exactly
   the supported surface. No new syntax (notably, no fenced ```math) was
   added, and the Markdown scanner was not expanded.

3. **Binary installation semantics.** `setup.py` and `doctor.py` now agree:
   the configured MathJax renderer is a required dependency of a fully ready
   installation. `setup.py` fails clearly with a non-zero exit when Node/npm
   are unavailable (it no longer prints a soft warning and returns success),
   and it no longer prints "Standalone runtime ready" when the math dependency
   is not installed. `doctor.py` already treated a missing renderer as
   unhealthy in its `ok` aggregate; its stale comment was aligned. There is
   exactly one readiness level — ready or not — no "math-free ready" tier.

**Terminology.** "target renderer" / "real MathJax" wording was narrowed to
"configured MathJax renderer" across `math_preflight.py`, `citations.py`,
`setup.py`, `doctor.py`, and this note, to state exactly what is being
exercised.

**Robustness tests added** (`tests/test_reporting.py`):
- `TestMathPreflightResultProtocol` — cardinality (fewer/extra results),
  shape (non-list, missing `ok`, non-bool `ok`, rejection without error,
  empty error), the valid-contract pass/reject path, unparseable output, and
  pipeline placement (protocol check fires at the audit boundary before the
  Reader). All mock the subprocess boundary, never the production validator.
- `TestMathPreflightSupportedSurface` — pins the four supported forms and the
  deliberate non-support of fenced ```math and inline-code math.

No new ADR and no v0.6.5 document was created; this section updates the
existing completion note in place, per the patch spec.
